## ✨ What's New

- 🚦 **`fetchRequested` can now cancel the interception** — the event payload gained a `result` object (`{ canStart: true }`). Set `result.canStart = false` and the engine leaves the request completely untouched: no `respondWith`, no router, no fetch plugin and no global listener.

  ```javascript
  engine.on('fetchRequested', ({ url, result }) => {
    if (url.pathname.startsWith('/__internal')) result.canStart = false;
  });
  ```

- 🧩 **New `FetchStartCheckerResult` / `FetchStartCheckerValues` typedefs** — the guard object is fully typed, and listeners may attach arbitrary extra properties to it so later listeners can read them.

## 📝 Documentation

- 🎧 **`TinyServiceWorker`** — documented that `sw:PrepareUpdate` is a message and not an event, that `sw:RegistrationFailed` is never emitted, and that `autoNotifyPush` is a getter **and** setter that throws on non-booleans.
- ⚙️ **`TinyServiceWorkerEngine`** — added the `push` and `sync` config blocks, the `PUSH_TYPE` enum, the full **Events Reference** table, the `ApiHandlerOptions` table, the `fetchRequested` bail-out section, and the `globalMsgCode` validation rules.
- 🧵 **`TinyWebWorker`** — clarified that the worker must post `{ type: 'ww:EngineReady' }` (or use `TinyWebWorkerEngine`), and documented what `terminate()` actually detaches.
- 🛠️ **`TinyWebWorkerEngine`** — documented `offApi()`, the `useLogColors` option and the `{ data, correlationId }` handler contract.
