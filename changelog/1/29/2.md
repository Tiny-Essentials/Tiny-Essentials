## 🚀 New Features

* **YouTube Utils**: A tiny, dependency-free helper for YouTube links. 🎬
  * **`extractYouTubeVideoId`**: Accepts a raw 11 character id or any `youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtube-nocookie.com` and `youtu.be` URL (`watch`, `embed`, `shorts`, `live`, `v`) and returns the canonical video id.
  * **`getYouTubeThumbnailUrl`**: Builds the thumbnail URL for every supported quality (`default`, `mqdefault`, `hqdefault`, `sddefault`, `maxresdefault`) without any network request.
  * **`fetchYouTubeOEmbed`**: Fetches and validates the official oEmbed metadata, with an injectable `fetch` and `AbortSignal` support.
  * **`assertYouTubeOEmbedResponse`**: Deeply validates an oEmbed payload and returns a brand new, fully typed object.
  * Ships with a browser playground at `test/html/basics/youtube` and a Node.js suite (`npm run test:mjs:youtube`).

* **Media Loader Suite**: A brand-new set of libraries dedicated to loading and caching media assets. 🎞️
  * **`TinyMediaLoader`**: The core loader for fetching media assets with progress tracking and cache support. 📦
  * **`TinyImageLoader`**: A specialized loader for images. 🖼️
  * **`TinyAudioLoader` (TEST)**: A specialized loader for audio files. 🔊
  * **`TinyVideoLoader` (TEST)**: A specialized loader for video files. 🎬
  * **`TinyMediaCache`**: A caching layer to avoid re-downloading media that was already loaded. 🗄️
  * **`TinyMediaProgress`**: A helper for tracking and reporting loading progress. 📊

### 🧠 `TinyMediaLoader`

* **Progressive loading**: new `progressive` option (enabled by default) renders the media while the bytes are still arriving instead of waiting for the whole payload.
* **HTTP `HEAD` pre-flight**: the new `useHeadRequest` option fetches the response headers before the download starts, so `Content-Length`, `Content-Type` and friends are available up front. The raw objects are exposed through `response` and `headResponse`, and the new `httpHeaders` metadata field carries every captured header.
* **`TinyMediaMirror`**: concurrent loads of the same URL are now deduplicated. The second loader attaches to the download that is already running, replays the events emitted so far and shares the very same `Blob`. Controlled by the new `mirror` option (enabled by default) and observable through the `mirrored` getter and the `mirror` event.
* **Request body**: the `body` option (and `body` getter/setter) forwards a payload to the transport, which is required by endpoints that only accept `POST`, `PUT` or `PATCH`. It is ignored by `GET`/`HEAD`, and `_requestInit.body` still wins when both are set.
* **Cache probes**: `isCached(src?)`, `peekCache(src?)` and the `cached` getter inspect the shared cache without acquiring a reference or touching the `hits`/`misses` counters, and the `pending` getter reports whether a mirrored download for the current source is already in flight. `TinyMediaCache` gained the matching read-only `peek(url)` method.
* **Chunk level events**: the new `chunk` event streams every downloaded `Uint8Array` together with the `loaded`/`total` counters.
* **Typed events**: the whole event surface is now described by the `MediaLoaderEvents` typedef and consumed through `ICustomEventEmitter`, so `on`/`once`/`emit` are fully typed.
* **Pluggable transport**: `_fetch` and `_requestInit` are now overridable, which allows subclasses to inject a custom `fetch` implementation, headers, credentials or a request body.
* **Richer metadata**: `animation` now carries the full `AnimationProbeData` and `httpHeaders` exposes the response headers.
* **Hardened validation**: every constructor option is validated and throws a descriptive `TypeError`/`RangeError` instead of failing later.

### 🖼️ `TinyImageLoader`

* **Full animation control** with four modes: `none`, `native`, `script-only` and `controlled`.
* **Frame extraction** for `GIF`, `APNG`, `WebP` and `AVIF`, with the individual frames stored in a dedicated `TinyMediaCache`.
* **Playback API**: `play()`, `pause()`, `freeze(frameIndex)`, `unfreeze()` and the `playbackRate` setter.
* **`animationScript`** getter/setter to inspect and rewrite the per-frame delays.

### 📥 `TinyFetchLoader`

* **New generic loader** for arbitrary files, built on top of `TinyMediaLoader`.
* Supports `blob`, `arraybuffer`, `text` and `json` response types through the `responseType` option.
* `clone()` creates an independent loader that reuses the shared cache and the custom `fetch` by reference.
* `exportFetch()` returns a `fetch`-compatible function backed by the loader, which makes it a drop-in replacement for `globalThis.fetch`.

### 🗄️ `TinyMediaCache`

* **`maxBytes`**: new byte budget, enforced together with `maxItems`.
* **Parent/child links**: `set()` accepts a `parent` key, `children(url)` lists the owned keys and the `links` getter reports how many entries own at least one child. Deleting the last child now removes the parent as well.
* **Stricter validation**: `set()` validates `pinned`, `metadata` and `parent`, and `entries()` returns a defensive copy of the metadata.
* **New `links` counter** in `stats`.

### 🧪 `TinyBufferReader` / `TinyIsoBox`

* Every read is now bounds-checked and documented, and `has()`, `skip()` and `#require()` reject non-integer or negative counts.
* `TinyIsoBox` gained complete JSDoc for the box traversal helpers.

## 🛠️ Improvements & Refactors

* **`TinyPkgExportValidator`** was rewritten to follow the official Node.js `package.json` documentation:
  * Full support for **wildcard targets** (`./css/*.css`), validated against the file system.
  * `null` targets are now accepted and reported as excluded subpaths.
  * Arrays (fallback lists) are traversed, and empty arrays/objects are reported as invalid.
  * New validations for subpath keys, condition keys, path traversal (`..`), URL schemes and invalid characters.
  * New message templates: `itemSkipped`, `itemPattern` and `itemInvalidTarget`.
  * `validate()` now returns `false` (instead of `true`) when `package.json` was never loaded.

## 🎨 DeepStrap (Bootstrap 5.3 theme)

* **New `deepstrap` theme** with a token based architecture: colors, spacing, typography, effects and utilities are all driven by overridable Sass maps and CSS custom properties.
* **New components**: ghost buttons, contrast buttons, cube icon and sphere pulse indicator.
* **New background grid** helper (`_background-grid.scss`).
* **New Bootstrap 5.3 playground** with a live matrix of every component, section filter and theme switcher.
* **File renames** (breaking for direct imports):
  * `Placeholder-Colors-Fix.scss` → `input/_placeholder-colors-fix.scss`
  * `Spacing-Plus.scss` → `spacing/_spacing-plus.scss`

## 🐛 Fixes

* **`TinyHtml.toggleClass`**: the `force` parameter is now correctly documented as optional.
* **`TinyFS`**: removed the invalid `@override` annotations from the OPFS and Storage Bucket backends.
* **`TinyWebWorkerEngine`**: removed the invalid `@override` annotation from `emit`.
* **`package.json`**: every entry point now ships a `"types"` condition, so TypeScript resolves the declarations without `moduleResolution` workarounds.
